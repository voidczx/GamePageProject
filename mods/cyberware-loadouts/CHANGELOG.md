# Changelog

## 0.3.1 - 2026-08-22

- 修复 0.3.0 点击保存时的 DEP 崩溃：保存热路径仍会遍历库存并通过错误的弱引用 `out` 参数调用 `RPGManager.CyberwareHasSideUpgrade`，与“保存只读取装备槽”的设计目标不符。
- 保存现在只复制原生装备槽中的 `ItemID`、区域、槽位和 Cyberdeck 程序，不再查询或映射任何骨骼词条关系；手动装卸同样不会触发本 Mod 的词条解析。
- 词条兼容移到用户明确点击“装备”后的 resolver：它只读取真实库存候选的静态 `Item_Record.SideUpgradeItem` 关系，将已消失的临时 side record 唯一映射到 backing；完成比对接受 backing 与其 side record 的逻辑等价，成功后持久化稳定 backing 身份。多个 backing 候选仍会拒绝应用。

## 0.3.0 - 2026-08-22

- 推翻此前预设存储架构。0.2.0 实机连续出现两次不同形式的内存破坏：手动安装骨骼义体时读取随机失效地址，点击保存时跳转到堆地址并触发 DEP；仅更换持久化类型名称没有解决问题。
- 删除 `persistent array<ref<CyberwareLoadoutPreset>>`、持久化 `CyberwareLoadoutEntry` 以及其中的嵌套 `array<ref<...>>`。新 `CyberwareLoadoutsV3` 系统只持久化平行的基础值数组，运行时才解码为临时对象。
- 面板读取空预设不再创建或写入任何持久化自定义对象；保存会先验证完整快照，再以扁平的 preset index、entry ordinal、area、slot、ItemID、TweakDBID、program ID 和 attachment slot 写入。
- 骨骼义体及词条 backing 映射功能完整保留；本次修改仅替换存储层，不跳过任何义体区域。

## 0.2.0 - 2026-08-21

- 根据实机隔离结果进行持久化硬重置：启用 0.1.10 时手动卸除骨骼义体会触发 DEP 崩溃，禁用本 Mod 后同一操作正常。新版本改用全新的 `CyberwareLoadoutsV2` 模块和 ScriptableSystem 身份，完全不反序列化、不迁移 0.1.x 的预设对象；三套方案从空白重新保存。
- 保留完整骨骼义体预设功能，不排除或跳过该装备区域。保存时只从真实库存 backing 的稳定 `SideUpgradeItem` 关系映射当前词条派生记录。
- 不再对槽内瞬态 side `ItemID` 调用 `RPGManager.CyberwareHasSideUpgrade` 或其他原生身份接口；不读取动态 `StatsShard`，不计算随机派生 ID，也不生成或恢复派生物品。
- 将 `RipperDocGameController` 上的预设标签从动态 `array<wref<inkText>>` 改为三个独立弱引用，避免在原生 UI controller 扩展字段中持有可变动态缓冲区。

## 0.1.10 - 2026-08-21

- 完全删除预设版本识别、迁移、`[旧 / RESAVE]` 标记和首次保存自动清空逻辑。升级后由用户逐槽手动覆盖保存，不再让脚本判断旧数据格式。
- 修复 0.1.9 点击保存时进入骨骼派生义体动态身份匹配后读取空地址的实机崩溃。保存路径不再读取派生 `StatsShard`，也不再调用 `ItemID.DuplicateRandomSeedWithOffset`。
- 词条骨骼义体改为只通过玩家真实库存中的稳定关系映射：唯一一个 backing 的 `SideUpgradeItem` 指向当前派生记录时，保存 backing 的精确 ID；多个候选直接拒绝保存，不猜测实例。
- 快照捕获现在返回显式结果；保存、应用预检和装备批次都会在身份映射失败时于任何预设覆盖或装备变化前停止。

## 0.1.9 - 2026-08-21

- 修复 0.1.8 在旧存档的持久化预设类中间插入 `schemaVersion`、改变既有 `entries` 动态数组布局的回归。实机在手动安装会生成词条派生项的骨骼义体时，脚本运行时于 `DynamicBuffer::ResizeBuffer` 读取悬空地址并崩溃。
- 完整恢复 `CyberwareLoadoutPreset` 的原始字段布局。数据版本现在复用系统原本已有但未读取的 `lastAppliedPreset` 字段，以 `1000+` 标记新格式，不再向已持久化的预设类增加字段。
- 第一次成功保存新版方案时会一次性清空三套旧方案，再保存当前槽位；失败或空捕获不会清空旧数据。旧方案仍会在任何身份解析和装备请求前被拒绝。

## 0.1.8 - 2026-08-20

- 停止自动迁移 0.1.0–0.1.7 保存的旧预设。第二份 0.1.7 实机崩溃转储仍为读取空地址，证明仅移除诊断不足以让旧瞬态 side `ItemID` 的运行时迁移变得安全。
- 为预设新增持久化 `schemaVersion`。旧预设在当前装备快照、候选构建、任何 native 身份解析和装备请求之前直接返回明确错误，并在 UI 标记为 `[旧 / RESAVE]`；不会修改装备。
- 新保存的预设使用当前 backing original 规范化模型并标记为版本 1。用户需要手动恢复想要的旧配置并覆盖保存一次，之后才能应用。

## 0.1.7 - 2026-08-19

- 修复 0.1.6 在应用旧预设时的崩溃：REDengine 报告为读取空地址，CET 日志精确中断在逐项序列化已被原生删除的旧 side-upgrade `ItemID`；崩溃发生于旧预设解析和任何装备变更之前。
- 完全移除一次性 `LogChannel` 诊断、逐条旧物品状态探测及其 CET 可选依赖，发布版不再对已消失的瞬态实例执行日志型原生查询。
- side-upgrade 规范化改为以 backing record、装备区域和原生生成的 `StatsShard` 身份进行唯一匹配；不依赖会“返回首个匹配项”的原生反查辅助函数。旧预设迁移仍坚持唯一候选，否则安全拒绝。

## 0.1.6 - 2026-08-19

- 修正对骨骼义体 side-upgrade 生命周期的理解：词条专长生成的是仅在装备期间存在的派生实例，玩家实际持有的是对应的 backing original；卸下派生实例时原生游戏会主动删除它，并非义体财产丢失。
- 保存、当前装备快照、完成比对和回滚现在都会通过原生 `GetOriginalItemIDFromSideUpgrade` 将派生实例规范化为玩家实际持有的基础实例；应用方案时只装备基础实例，由原生 `PowerUpCyberwareEffector` 重新生成词条版本。
- 旧版预设中的派生记录仅在库存里能唯一确定对应基础实例时自动迁移；多个候选会继续安全拒绝。Mod 不再拦截 `UnequipItem`，也绝不通过 `GiveItems` 固化或复制临时派生义体。

## 0.1.5 - 2026-08-19

- 诊断候选版，曾把派生 side-upgrade 误判为丢失的库存实例并尝试恢复；原生脚本与后续实机信息证明该模型不正确，此版本未作为最终修复交付，相关逻辑已在 0.1.6 完全撤销。

## 0.1.4 - 2026-08-18

- 加入一次性结构化诊断日志，覆盖保存快照、Apply 预检、forward/rollback 的卸载前、卸载后与最终比对阶段。
- 解析失败时记录保存槽区、物品记录、静态装备区域、实例哈希、候选来源、`GetItemDataByTDBID` 对照、所有权以及 `used`/`reserved` 排除原因。
- UI 错误中的 TweakDBID 改用 `TDBID.ToStringDEBUG`，不再显示空白记录名。
- 该版本用于确认“真实槽位区域与物品静态区域不一致”或“已卸载义体未进入 `GetItemList`”等剩余根因；没有再次猜测性放宽安全匹配。

## 0.1.3 - 2026-08-17

- 修复两套方案之间切换后，仍归玩家所有的义体因动态 `ItemID` 漂移而被误报为“缺少具体义体实例”。
- 新增运行时实例解析：精确 ID 优先；失效时仅接受同物品记录、同装备区域且未占用的唯一候选，多候选安全拒绝。
- 义体和 Cyberdeck 程序会在预检、卸载后及完成比对前重新解析；rollback 使用同一解析路径。
- completion 携带本批次的实际目标身份；成功后只用权威装备快照重绑定当前应用的预设。
- 先预留仍有效的精确实例，再解析失效 ID，使同记录多实例的结果不再受保存顺序影响；每个事务阶段继承上一阶段已确认的绑定。

## 0.1.2 - 2026-08-17

- 修复已安装在 Cyberdeck 内的快速破解程序不被顶层 `HasItem` 识别，导致刚保存的方案立即应用仍提示缺少程序的问题。
- 完全相同的当前方案现在会在破坏性预检前直接返回成功。
- 真正切换时同时接受背包程序与当前已安装程序，并在卸载阶段后再次确认程序已回到可安装状态，否则自动回滚。
- 拒绝重复引用同一程序实例或同一 Cyberdeck attachment slot 的损坏预设。

## 0.1.1 - 2026-08-16

- 修复正常开放世界 `SceneTier1` 和普通 Hub/义体界面的 `LockInHubMenu` 导航标签被误判为剧情或受限区域，导致方案无法装备的问题。
- 将剧情层级、游泳和终结技工作点拆成独立提示，便于识别真正的安全门禁。
- 保存和装备按钮改为固定 72 px 高命中框并居中文字，不再被 `SetFitToContent` 收缩，改善手柄虚拟光标操作。
- 为上述两项回归加入发布前静态断言。

## 0.1.0 - 2026-08-16

- 在原生义体界面和 RipperDeck 界面中加入 3 套义体预设。
- 预设随游戏存档持久化，保存精确义体实例、槽位及 Cyberdeck 程序的 attachment slot，不生成缺失物品。
- 加入战斗、载具、受限玩家状态、任意非默认时间膨胀、主要义体主动效果和义体武器抽出门禁。
- 加入所有权、可装备性、精确槽位、义体类型、Humanity/Capacity Booster 全量预检。
- 改用单个 EquipmentSystem 串行批次、权威完成回调、非强制原生装备处理器和请求式失败回滚。
- 拒绝空方案，避免误触发全部卸载。
- 发布包使用文件白名单并生成 SHA-256，不携带 redscript 日志或缓存。
- 验证矩阵覆盖 Cyberpunk 2077 2.31 基础脚本、RipperDeck 1.1.0、Cyberware-EX 1.5.6、Codeware 1.20.3 与 TweakXL 1.11.4。
